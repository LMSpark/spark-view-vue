# SPARK_VIEW 视频系列制作圣经

## 统一定位

本系列面向中高级前端工程师、低代码平台架构师、企业后台平台开发者和 AI 工具调用工程师。口吻要像技术负责人带读源码：结论明确，术语准确，画面干净，不做营销式空话。

## 长短视频差异

- 长视频：6-10 分钟，允许解释背景、机制、源码锚点和图解链路。
- 短视频：90-180 秒，只保留冲突、关键判断和一个可传播结论。
- 每集短视频结尾统一引导：“完整源码链路看本集长视频。”

## 视觉风格

- 主视觉使用 `docs/blog-series/assets/*.svg`。
- Mermaid 图用于机制解释，画面中尽量高亮 1 条路径，不同时展示过多节点。
- 源码画面只展示关键文件名、函数名和 3-8 行上下文，不滚动长代码。
- 字幕采用短句，避免一屏超过两行。

## 硬口径

- 权限：前端权限只是 UI 装饰和体验约束，真正安全边界在后端鉴权。`_modelPerm` / `_perm` 是后端下发的权限快照事实源，`permAction`、`permissionMode`、字段渲染和按钮显隐是消费端。
- AI：AI Runtime 是通用受约束业务智能体架构。core 管会话、注册、投影、翻译和历史；业务模块管领域语义、函数目录、知识 payload 和执行器。PageDesign 是首个完整样例。
- Component PayloadProvider：组件参数荷载指南属于 PageDesign knowledge 业务模块，不属于 core 层业务能力。

## 禁忌表达

- 不把前端 UI 表现写成安全边界。
- 不把 AI Runtime 写成 PageDesign 的内部工具。
- 不把 SPARK_VIEW 写成普通 JSON 表单生成器。
- 不把 DataSet 描述成数据库，也不套用数据库外键、索引、事务等口径。

## 每集固定结构

长视频：

1. 真实问题开场。
2. 一句话结论。
3. 核心机制图解。
4. 源码锚点跟读。
5. 本集价值收束。
6. 引出下一集。

短视频：

1. 冲突钩子。
2. 关键判断。
3. 一个机制画面。
4. 结论和长视频引导。
