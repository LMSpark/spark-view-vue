# 第 01 集长视频稿：别再叫它 JSON 表单：SPARK_VIEW 的页面资产化野心

目标时长：6-10 分钟  
来源文章：`../../blog-series/01-spark-view-not-json-form-generator.md`  
核心句：SPARK_VIEW 的目标不是把表单写成 JSON，而是把企业后台页面变成可治理的软件资产。

## 口播稿

### 00:00 开场

很多人第一次看到配置化页面，会本能地把它归类成 JSON 表单。这个判断在简单场景里没问题，但放到企业后台就会失真。后台页面不只是字段布局，它还要处理数据联动、权限快照、树数据、聚合、脚本、预览和长期维护。

### 01:20 核心判断

SPARK_VIEW 真正想做的是页面资产化。页面不再是一份一次性代码，也不是一段孤立 JSON，而是一组可以被加载、编译、预览、测试、回滚和 AI 修改的资产。四文件协议就是这个思路的入口。

### 03:00 源码跟读

画面切到 `package.json` 和 `packages/README.md`。这里不是单包组件库，而是应用集成、组件解释、数据内核、配置加载和 AI 能力协作的 monorepo。再切到 `docs/SPARK_VIEW_PROJECT_DEEP_DIVE_ZH.md`，强调系列不是宣传“配置驱动”，而是解释一套长期治理模型。

### 05:30 图解总结

用图解释三种路线：表单生成器解决字段渲染，代码生成器解决初始开发效率，SPARK_VIEW 解决页面作为资产的长期演进。它把结构、数据、行为和样式拆开，再交给稳定运行时解释。

### 07:30 收束

这一集只建立基本判断：不要把 SPARK_VIEW 看窄。下一集进入它最核心的资产边界：四文件协议。
